### Fixed
- **A killed lock connection behind `pgbouncer-transaction` is no longer silent.** Advisory locks held in a pinned transaction (named, scheduler, bootstrap, audit-checkpoint and audit-index-build locks, and the server-presence lock) are now pinged every 5 seconds. A lock holder whose connection died gets its context cancelled with `ErrAdvisoryLockLost` and an error from the call; a server whose presence lock was lost logs it and shuts down with a failure status instead of running beside a possible admin command. Guarded by `TestWithNamedLock_TransactionPooling_KilledLockBackendIsReported` and `TestPgBouncer_ServerGuard_LostPresenceLockIsReported` (`pg_terminate_backend`). Direct and `pgbouncer-session` connections are unchanged. See `docs/postgresql-poolers.md`.
