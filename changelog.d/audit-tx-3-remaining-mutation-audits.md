### Security
- **Every remaining security-relevant change now writes its audit record in its own transaction, and no revocation can lose its record.** Project and environment update / delete / restore, group create / update / restore, user update / reactivate / restore, one-time password reissue, SCIM user and group provisioning writes, invitations, access-request create / reject / approval, and the configuration changes (notification channels and retry policy, anomaly config, rotation policies, alert escalation policies, risk exceptions, legal hold, machine and token classification, access-review campaigns) commit with their audit row on SQLite and PostgreSQL; if the row cannot be written the request fails and nothing changes. Revocations (role, group, permission, share, ACL, token, session and PAT revoke; user suspend, deactivate and delete; SCIM deprovision; break-glass revoke; expiry sweeps) are still never blocked by the audit log, but they now commit together with a record of the audit row they owe: a refused append or a crash right after the commit queues the row for the existing backfill instead of losing it, and the cache eviction runs before the append so the audit log never delays a revocation taking effect. Inventory: `docs/specs/security-mutation-audit-inventory.md`. Guarded by `TestSecurityMutationAudit3_RowExistsIffMutationCommitted`, `TestRevocationAudit_EffectCommitsAndRowIsOwedNeverLost` (error, effect-then-error, panic and crash at the append, SQLite and PostgreSQL) and the router-level `TestAuditTx3Mutation_AuditFailureFailsClosedChangesNothing` and `TestAuditTx3Revocation_AuditFailureDoesNotBlockAndRowIsOwed`.

### Changed
- **Project, environment and alert-escalation-policy audit rows are written by core, not the HTTP/gRPC handlers.** The handlers tag the request context with the actor; internal callers that do not tag it write no row from core, as before. Deleting a project now also fails closed on its machine-identity cascade events instead of logging them best-effort.
