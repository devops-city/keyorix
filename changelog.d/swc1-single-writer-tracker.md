### Added
- **`storage.database.single_writer`: the server's own writes to the security tables are tracked synchronously.** Every connection of a single-writer server reports its statements to an in-process tracker. A committed write to a fenced table moves a generation before the call returns, which the authoritative caches of the next change validate against. The poller cross-checks the database's write epoch: an epoch move no in-process write explains is flushed, logged as an error and counted (`unattributed_bumps` in `GET /api/v1/system/info`). No cache consumes this yet; with the setting off nothing changes.
