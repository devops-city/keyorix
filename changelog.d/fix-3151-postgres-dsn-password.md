### Fixed
- **`storage.database.dsn` no longer silently ignores the database password (#3151).** With `storage.type: postgres` and a `dsn` that carries no password, the password from `KEYORIX_DB_PASSWORD` / `KEYORIX_DB_PASSWORD_FILE` (or `storage.database.password`) is now added to the connection string; before, it was dropped and the failure surfaced as `connection reset by peer`. If the `dsn` already contains a password and one of those sources is also set, startup (and every command that opens the database) now refuses with an error naming the setting and the fix (remove the password from the `dsn`, or unset the other source) rather than choosing one; the error never prints either password. Passwords containing spaces, quotes or backslashes are now quoted correctly in the field-by-field form. Documented in `docs/CONFIGURATION.md`.
