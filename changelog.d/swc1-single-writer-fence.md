### Added
- **`storage.database.single_writer` (opt-in, PostgreSQL, one server): holder lock, write fence and write epoch.** With the setting on, the server takes a per-schema advisory lock at start-up (a second server, a server without the setting, and `admin --force` are refused while it runs), installs triggers that refuse every direct database write to the security tables from any other session while it runs, and polls a write epoch with a 1 s lease. If the fence cannot be installed and verified, the server refuses to start. The live state is in the start-up log, `GET /api/v1/system/info` (`database.single_writer`) and `admin validate --posture`, with the emergency two-step for a direct change (docs/single-writer.md). This release changes no cache: reads still confirm against the database. Off by default; with it off nothing changes, except that a start-up refuses while a single-writer server holds the database and removes a fence one left behind.
