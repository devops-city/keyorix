### Security
- **A role grant, credential or other access-granting change can no longer commit without its audit record.** Role grants (direct, JIT, SSO-mapped, baseline backfill, project member add, access-request approval), group role grants and memberships, permission and role-definition changes, break-glass activation, secret shares and share updates, secret ACL grants, machine identity create / token issue and rotate / role grant, PAT create, user create (with or without assignments, setup link, one-time password), project and environment create, and SoD policy create/delete now write their audit rows in the same database transaction as the change, on SQLite and PostgreSQL. If a row cannot be written the request fails and nothing changes; a crash at the audit append leaves no unaudited grant. Revocations (role/share/ACL/token/session removal, suspend, delete) are unchanged: they are never blocked by the audit log and still audit after their commit. Inventory: `docs/specs/security-mutation-audit-inventory.md`. Guarded by `TestSecurityMutationAudit_RowExistsIffMutationCommitted` (error, effect-then-error, panic and crash at the append), `TestSecurityMutationAuditFailure_FailsClosedChangesNothing` (32 REST/gRPC operations) and `TestTracker_GrantWithItsAuditRowIsOneFencedWrite` (single_writer).
