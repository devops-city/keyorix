- **INV-CLI-secrets-never-on-argv** A secret is never accepted as a command-line flag or positional argument: every string flag that carries one is listed in `refusedSecretFlags` (cli/cmd/secretflags.go), hidden from `--help`, and refused with a message that names the safe way in (hidden prompt, stdin, `--from-file`, or a `KEYORIX_*[_FILE]` variable) and never repeats the value; every other secret-looking flag or positional is explained in `notSecretFlags`. `KEYORIX_ALLOW_INSECURE_SECRET_FLAGS=1` restores the old warn-and-accept behaviour for scripts being migrated. Why: argv is visible to every local user through ps and stays in shell history and CI logs (CLI-LOGIN-001, DOCS-SECRETS-1, SCRIPTS-SECRETS-1); a warning is not a rule. Guard: `cli/cmd/secretflags_test.go:TestSecretFlagsAreAllClassified` (family sweep over every flag and positional of the command tree; a new `--api-key` fails it), `TestRefusedSecretFlagsAreRefused` (every entry, on the real tree, canary value never echoed, escape hatch works), journey `TestJourney_CLISecretsNeverOnTheCommandLine`; docs: `docs_no_literal_secrets_test.go`. The journeys' harness (`CLIEnv`) sets the escape hatch until they are moved off `--value`/`--password`.
