- **INV-CLI-ca-file-narrows-trust** A configured CA file (`--ca-file` > `KEYORIX_CA_FILE` > `ca_file` in the credentials file, resolved in `cli/cmd/client.go:resolveCAFile`) replaces the system roots with exactly that file's certificates for every `newAPIClient` call; it never disables verification, and a missing, empty, key-bearing or group/world-writable file fails the command instead of falling back. The pool comes from Go's x509 reading the file, not `SSL_CERT_FILE`, so it behaves the same on macOS. Why: SECURE-DEFAULT-1 (`keyorix-server admin init` generates a self-signed server certificate). Guard: `cli/internal/apiclient/ca_file_test.go` (`TestHardenedClient_SelfSignedServerRefusedWithoutCA`, `TestHardenedClient_CAFileDoesNotTrustOtherServers`, `TestLoadCAPool_FailsClosed`), `cli/cmd/ca_file_test.go` (every source, driven through real commands).
