Keyorix has been deployed as release "{{ .Release.Name }}".

1. Wait for the pods to be ready:

   kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }} -w

2. Reach the UI:
{{- if .Values.ingress.enabled }}

   http{{ if .Values.ingress.tls }}s{{ end }}://{{ .Values.ingress.host }}
{{- else if .Values.web.enabled }}

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "keyorix.web.fullname" . }} 8080:{{ .Values.web.service.port }}
   open http://localhost:8080
{{- else }}

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "keyorix.server.fullname" . }} 8080:{{ .Values.server.service.port }}
{{- end }}
{{- if and .Values.ingress.enabled (not .Values.ingress.tls) }}

⚠️  WARNING — ingress.tls is empty, so this Ingress serves plaintext HTTP only.
    Session cookies, PATs, and login passwords will cross the wire unencrypted
    unless TLS already terminates upstream (e.g. a cloud load balancer). Set
    ingress.tls to enable HTTPS at this ingress, or confirm upstream TLS
    termination is in place.
{{- end }}

{{- if .Values.auth.adminPassword }}

3. Log in with the admin you configured (auth.adminUsername="{{ .Values.auth.adminUsername }}").
{{- else }}

3. No admin password was set. Initialise the first admin manually, over the
   network, against the address from step 2 (e.g. the port-forwarded address),
   using the bootstrap token this release generated:

   kubectl -n {{ .Release.Namespace }} get secret {{ include "keyorix.fullname" . }} \
     -o jsonpath='{.data.KEYORIX_BOOTSTRAP_TOKEN}' | base64 -d; echo

   read -r -s -p 'Bootstrap token: ' KEYORIX_BOOTSTRAP_TOKEN; echo
   export KEYORIX_BOOTSTRAP_TOKEN
   keyorix system init --server http://localhost:8080

   (The CLI reads the token from KEYORIX_BOOTSTRAP_TOKEN and prompts for the admin
   password; neither belongs on the command line.)
{{- end }}

⚠️  CRITICAL — back up the encryption keys volume
    The PVC "{{ include "keyorix.server.fullname" . }}-keys" holds the wrapped DEK
    and KEK salt. It is annotated helm.sh/resource-policy: keep, but if you lose it
    OR change auth.masterPassword, every stored secret becomes undecryptable.
